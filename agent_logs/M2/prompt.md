## 二、M2研究目标

原始GraphMAE采用随机均匀的节点特征掩码。

本阶段尝试设计一种基于节点度数的自适应掩码策略：

Degree-aware Masking。

核心假设：

高度数节点具有更多邻居上下文信息，适当提高其特征被掩码的概率，可能改善模型对这部分节点的表示学习。

但这只是研究假设。

度数加权也可能导致模型过度关注高度数节点，损害低度数节点的表示学习。

因此本阶段需要通过实验判断其有效性，不得预先认定改进方法优于原始方法。

## 三、算法设计

### 1. 度数计算

使用M1相同的Cora数据和图结构。

具体要求：

1. 从M1使用的预处理后图结构中计算节点度数。
2. 排除所有自环。
3. 核查原始边是否双向对称。
4. 如果存在重复边，计算唯一邻居数量，避免重复计数。
5. 对无向图使用每个节点的唯一邻居数量作为度数。
6. 不使用节点类别标签计算度数。
7. 保存完整度数向量、度数分布及SHA256。

度数只计算一次，所有实验共用。

需要记录：
- 最小度数。
- 最大度数。
- 平均度数。
- 中位数。
- 不同度数节点的数量分布。

### 2. 掩码权重

使用：

w_i = (d_i + 1)^alpha_d

其中：

- d_i：节点度数。
- alpha_d：度数加权系数。
- w_i：节点掩码采样权重。

设置四组实验：

| 实验组 | alpha_d | 策略 |
|---|---:|---|
| Baseline | 0 | 均匀随机掩码 |
| Experiment A | 0.25 | 轻度度数加权 |
| Experiment B | 0.5 | 中度数加权 |
| Experiment C | 1.0 | 强度数加权 |

注意：

alpha_d与GraphMAE原始SCE损失中的alpha_l不是同一个参数。

代码中统一使用degree_alpha命名，避免混淆。

### 3. 加权无放回采样

使用加权无放回采样选择需要掩码的节点。

推荐使用torch.multinomial(weights, num_samples, replacement=False)。

需要保证：

- 每轮被掩码节点数量与原始方法完全一致。
- 每个节点每轮最多被选择一次。
- 不允许重复采样。
- 不改变mask_rate。
- 不改变replace_rate。
- 不改变mask token。
- 不改变SCE损失。
- 不改变Encoder、Decoder及其他网络结构。

对于Cora：

节点数为2708，mask_rate为0.5。

应保持每轮掩码节点数量为1354，与M1一致。

Baseline必须保留原始均匀随机采样逻辑，而不是错误地把加权采样当作所有实验的共同方法。

### 4. 随机数管理与公平性

这是M2最重要的技术要求之一。

不同掩码采样方法可能消耗不同数量的随机数，从而改变后续Dropout等操作的随机序列，造成不公平比较。

请先阅读M1实际实现，检查：
- 原始节点选择使用的随机函数。
- 随机替换节点使用的随机函数。
- 特征替换使用的随机函数。
- Dropout使用的随机数来源。

优先采用以下方案：

1. 节点索引选择使用独立CPU torch.Generator。
2. 同一个seed的四个实验使用相同的掩码随机数种子。
3. Baseline使用原始均匀randperm选择节点。
4. 度数加权实验使用独立generator进行torch.multinomial采样。
5. 不允许加权采样额外消耗模型初始化、Dropout及其他训练过程的全局随机数。

如果原始节点选择使用全局torch随机数，为保证全局随机数状态一致：

- 在加权采样分支中，先执行与原始实现相同设备、相同形状的randperm操作，但丢弃其结果。
- 然后使用独立CPU Generator进行度数加权采样。
- 这样尽可能保持后续随机替换和Dropout的全局随机数调用顺序一致。

如果原始实现还有其他随机数调用，需要根据实际代码进行适配，不能机械照搬上述示例。

必须通过测试验证：

- 同一个seed下四组实验初始模型权重一致。
- 节点选择操作不会意外改变后续全局随机数状态。
- 模型初始化一致。
- 随机替换与Dropout的调用顺序保持一致。
- 所有实验均使用同一训练流程。

如果无法做到完全一致，需要明确记录实际差异及其影响，不得声称完全控制了随机性。

### 2. 度数分组分析

要求：

- 根据实际度数分布确定分组边界。
- 尽量保持同一度数的节点处于同一组。
- 记录每组节点数量、平均度数和边界。
- 如果分组因度数大量重复而不均衡，如实记录。

分别统计：
- 各组节点的实际掩码比例。
- 各组节点的平均被掩码次数。
- Baseline和改进方法的分组掩码差异。

验证度数加权策略是否真正改变了节点选择分布。

### 3. 不同度数节点的分类效果

只在最终确定Baseline和最佳Degree-aware方案后，使用测试标签进行一次分组评价。

分别计算低、中、高度数测试节点的：
- 样本量。
- 分类正确数量。
- Accuracy。

注意：
- 不能使用测试标签确定分组边界。
- 不能根据分组测试结果重新选择alpha。
- 小样本组的结果应谨慎解释。

### 4. 训练过程分析

比较Baseline与选定改进方法：

- SCE Loss曲线。
- Loss均值和标准差。
- 训练时间。
- GPU显存。

如果改进方法的Loss下降更快，但分类Accuracy没有提高，应当明确指出两者并不等价。
